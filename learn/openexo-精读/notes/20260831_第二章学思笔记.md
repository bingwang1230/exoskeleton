# 20260831 · 第二章学思笔记（设计目标与模块化哲学）

> 会话形式：learn 协议探讨式，概念 1 由大量用户追问驱动（鲍登线/RMSE/损耗账单），概念 2 由用户上午的模块化理论反推驱动。本笔记串思考脉络。

## 脉络总览

从七条设计目标的结构（壁垒的镜像）出发 → 每条目标的代价由物理写就（能源税/铜损坑/滚动滑动分野）→ 模块化机制（自由度搬家/抽象税/双速系统）→ 契约栈（硬件通用接口的理解）。第二章收敛为一句话：**设计目标是壁垒的镜像，每条目标的价格标签由物理写就；而模块化的本质是把自由度从代码搬到配置、把差异从契约下沉到配置。**

## 用户的三条思考主线

1. **量纲直觉的自觉训练**：主动要求「帮我算数量级」——从「直驱省摩擦」的定性直觉，进步到要求损耗分项账单；铜损 20× 收口题一次答对。
2. **真实基线思维**：「比较的基线不该是幻想中的全自研，而是反正要用第三方组件的现实」——概念 2 最锋利的一句，自发产出。
3. **跨域迁移**：软件的 API adapter 概念主动迁移去理解硬件接口（催生契约栈讨论）；nginx.conf vs fork 源码的双速同构一点就透。

## 误解与纠正记录

| 原表述 | 纠正 |
|---|---|
| 「任何场景可用」的代价是可靠性冗余设计耗电 | 是能源税本身：无缆=把能源背身上，锂电池能量密度是物理账 |
| 直驱省掉鲍登摩擦 → 电池利用率更高 | 省的是个位数瓦的摩擦，亏的是 ~20× 的铜损（τ² 定律）；减速比不是损耗是套利 |
| 直驱下「漂移不能像髋一样推断」 | 反了：直驱=刚性=可推断；鲍登漂移是现设计必须闭环的原因 |
| 模块化→接口简单→自由度减少 | 半对：自由度从代码搬到配置而非消失；指标应换成「下一次变更的成本」；抽象税总要有人付 |

## 概念金句银行

- 减速比不是损耗，是套利（铜损 ∝ τ²，楼梯每升一级省平方）
- 传动不只是把质量搬到腰上，更是让小电机待在高效工作点
- 助力设备的能耗大头在损耗不在做功（95W 里做功仅 10–20W，AI 反推待验证）
- 布线直线度是鲍登系统的生命线（capstan：损耗随弯角指数长，润滑只降 μ 降不掉 θ）
- 硬件契约没有 try/catch（违约的裁决者是物理）
- 自由度从「改代码」搬到「改配置」；抽象税总要有人付
- 契约吸收标准间差异（AK60↔AK80 同 CAN），配置吸收实例间差异（你手上这台的传动比/标定）
