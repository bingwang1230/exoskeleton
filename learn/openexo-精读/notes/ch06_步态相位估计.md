# 步态相位估计（髋控制器的地基：给自己造一块表）

## 概念定义

**问题起点**：踝 PJMC「跟随估计的你」看力；髋走另一条路——**时间触发的力矩曲线**（样条），自变量是步态相位 0–100%。所以髋控制器开机第一件事：**造一块表**。

**OpenExo 造表三件套**：

```
①事件源：跟 FSR——每次跟击 = 新周期的 0%
②周期估计：连续跟击间隔的滑动平均 = 期望周期 T̄（秒）
③读表：相位 = 距上次跟击经过的时间 ÷ T̄
```

**关键账**：
- **归一化**：人不是节拍器（快走 0.8s/步、慢走 1.4s/步），除以 T̄ 把秒换成 %——快走慢走共用一张 0–100% 地图。这就是「用户定义峰值/升降时间都用 %步态周期」的底层原因
- **滑动平均**：滤掉单步抖动（转身、犹豫步、避障步）。窗口大小材料未给——**待确认**，复现时查开源代码
- **跟+趾分工**：跟击定周期起点（stance 开始）；趾压力消失 = toe-off = 摆动相开始。两事件把周期切成站立/摆动两大段
- **每腿各一块表**：左腿的表不掺右腿事件
- **相位=用过去预测现在**：T̄ 是历史平均，本步实际 ±10% 波动，误差随周期推进累积——84% 起点特殊处理的伏笔（→ ch06_髋样条控制器）

## 学习过程

@2026-09-05

- 检验三问：①突然停下表怎样（半对：用户答「触发完最后一个周期就停」，缺「表是自由奔跑的时钟、相位会跑过 100% 不停」→ 必须代码写看门狗：超上限/无事件→零力矩，**AI 推断，材料未写，复现必补**——安全红线天然要求）②趾 FSR 当事件源行不行（结论对：语义变成摆动相开头；摔跤误触发帮倒忙=任何事件源的共性故障，靠看门狗不靠换源；AI 补刀**信号锐利度**：跟击=冲击事件时间戳准，离地=渐变卸载阈值糊——**跟击是敲门，离地是叹息**）③窗口太长遇跑走切换（全对：T̄ 拖长周期→表慢→助力错位→体感是阻力；跑步机定速走场景里这问题**不是解决了而是没遇到**）
- 用户澄清追问「除以 T̄ 除以什么」→ 符号要落地：T̄=期望周期（秒），例：T̄=1.0s、经过 0.3s → 相位 30%

## 关键洞察（金句）

- 髋控制器开机第一件事：给自己造一块表
- 表是自由奔跑的时钟——让它停的必须是代码，不是物理
- 跟击是敲门，离地是叹息：事件源的锐利度决定表的精度
- 窗口太长不是解决了节奏突变，是没遇到它
- 相位 = 用过去预测现在，误差在周期末尾累积（84% 偏移的伏笔）
