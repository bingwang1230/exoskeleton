# SD 卡配置化(换构型不改代码)

## 概念定义

- **物理**:Teensy 4.1 板载 SD 卡槽(FAT32 惯例),插普通 SD 卡;换构型=换卡,游戏卡带式,不连电脑。文件具体格式材料未给,ExoCode 验证 ⚠️。
- **卡里每一项都是树的一个决定**:侧/关节=树形;默认控制器=Controller* 指向哪个子类;传感器使用=Sensor[] 挂哪些;方向翻转=实例间差异(左右腿镜像装配压成一个布尔);传动比=机械常数;控制器参数=数值初值。
- **开机时序**:上电→挂载卡→解析→工厂按配置造树(new 好一切)→填初值→进 1kHz 循环(此后不准生长)。= docker-compose/k8s manifest 的嵌入式版;Spring XML bean 同古董。
- **双配置面边界**:SD=冷面(结构+初值,开机读一次,改=换卡重启);App/蓝牙=热面(只改数值,实时生效)。切分依据=「改了有没有中间态」:数值无(P 28→30 原子无缝),结构有(抽走正在 calc() 的对象=几毫秒未定义指令=人腿上失控)。

## 学习过程

@2026-09-04

- **「不准生长」澄清**(用户误读为不能改参数):生长=造对象动堆,不是写数值;字段随便写,堆不能动。最大力矩这类**安全限值**的 App 热改权限存疑(上限随手 40→60Nm=安全边界漂移),安全限值宜走冷面——ExoCode 验证。
- **通道纠正**:用户路径「Nano 经 CAN 告诉 Teensy」✗——三段链路三协议表(BLE 无线段/UART 独木桥/CAN 电机段),参数的腿永远是 UART,Nano 不会说 CAN。
- **断电持久化讨论**:用户方案=App 自管参数+连接下发+SD 只放默认(单一数据源,工程干净)——但漏两个场景:①裸奔窗口(开机→连接前用默认跑,人机认知分歧再现)②无 App 场景(户外没电/借穿,退化退太远)。行业惯例双保险:SD 存最后已知好配置+App 对账。论文做法未说,ExoCode 验证。
- **收官题判卷**(新助力曲线 SD 卡救不了么?):用户 ①不能✓②改源码✓③「SD=boot 文件,理论改 SD 上的源码」✗ 踏空——固件在芯片内部 Flash(USB 烧录),SD 是启动后读的数据盘,不含代码;改曲线=新 Controller 子类→编译→烧录→重启,SD 全程未参与。树莓派/GRUB 从卡加载程序是反例:物理可行,Arduino 生态选择分离——**这个选择恰好把双速系统物理化:分钟级的卡(实验员可改)vs 天级的芯片(程序员才能改)**。
- 配置系统本质收口:**预设词表内的自由度**;新形状=词表外新概念=慢车道+重付抽象税。第二章「赌注 90% 迭代落在词表内」的 10% 落网之鱼具象。

## 关键洞察(金句)

- **结构冷改,数值热改;切分线=「改了之后有没有中间态」**
- 方向翻转:左右腿差异压缩成一个布尔(实例间差异的极致压缩比)
- 分钟级的卡和天级的芯片——双速系统的物理化身
- 配置=预设词表内的自由度,词表外=慢车道+重付抽象税

## 误解与纠正记录

| 原表述 | 判定/纠正 |
|---|---|
| 「Nano 再通过 CAN 告诉 Teensy」 | ✗ CAN 是 Teensy→电机的总线;Nano↔Teensy 永远走 UART |
| 「不准生长=不能继续更新参数?」 | ✗ 生长=造对象(堆分配);写数值字段完全允许(热面本职) |
| 「SD 卡=Teensy 的 boot 文件,理论改 SD 上的源码」 | ✗ 固件在内部 Flash;SD=数据盘;代码/数据物理分离是生态选择 |
| 「断电持久化不需要,App 自管即可」 | 可行但漏裸奔窗口+无 App 场景;惯例双保险(SD 最后已知好配置) |
