## 1. 面包板两条轨：物理上毫无区别

- 每条轨下面都是**一整根磷铜弹簧夹**，与信号区 5 孔一组的夹子规格完全相同；板子不知道哪条是 3.3V 哪条是 GND；
- 轨的身份 = 我们把 ESP32 的 3V3/GND 接在了哪条上。**轨 = 一根顺路的长导线**（用于分发电源），不是电源本身（电源在 ESP32 体内）；
- 红黑线对调 → 两轨身份互换 → 电路变成「反接版」（不坏，但读数方向翻转）。
- 「地」不是大地，是**我们起名叫 0V 的公共回线**，所有电压都是相对它的高度。

## 2. 悬空为什么乱跳（裸重演第 3 题，已过）

- **断路 ≠ 0V**：0 是「锚」出来的（要有通往 GND 的路）；悬空 = 高度未定义。未压 FSR 读数稳定的 0，靠的正是 10k 那条锚腿；
- 充放电来源是**环境**不是「电源」：50Hz 工频场/人体/USB 噪声经杂散电容耦合 + ADC 采样电荷注入 + 泄漏；
- 一句话：**读数有意义 ⟺ 有参考路径**。

## 3. 分压术语与电压基准（当日最重要的纠正）

- 串联电路**分压不分流**（电流处处相等；分流是并联概念）；
- **D34 的读数 = V(中点) − V(GND)**：ADC 是一支以 GND 为海平面的高度计，量的是 **10k 那一份**电压；
- 换位验证（4kΩ 时刻）：正确版读数 = 4095×10/14 ≈ **2925**，反接版 = 4095×4/14 = **1170**，**两版之和恒为 4095**（量的本是互补的两块电压）；
- 「跟 3.3V 之间的电压差」（= FSR 那份）想直接量就反接——这就是反接版「越压越小」的原因。

## 4. GPIO 与 ESP32 引脚体系

- **GPIO = 通用输入输出**：芯片引脚的编号+身份，可编程设为输入（读电压）或输出（给电平）；34/35/36/39 四脚**硬件只读**（无输出驱动、无内部上下拉），天生适合传感器；
- 命名双轨制：GPIO34 = 芯片名，丝印 D34 = 开发板名，VP/VN = GPIO36/39。同一物理脚两套名字；
- ADC 分组：**ADC1（32–39）随时可用；ADC2（0/2/4/12–15/25–27）WiFi 开启即失效**。

## 5. strapping 与 D12 毒性

- strapping 脚（0/2/5/12/15）在**复位瞬间**被读作「开机拨码开关」；
- 其余脚拨错顶多进错模式（可救）；**D12 选 flash 供电电压：低=3.3V（对），高=1.8V → 读不了 flash → 无限重启**，拔线才活；
- 纪律：D12 永远空着（或只接纯输入不带pull-up的外设）；**排障口诀：莫名无限重启 → 先拔 D12 上的线**；
- 注意事项只在上电瞬间有效——启动完成后它就是普通 GPIO，但作为纪律整脚禁用。

## 6. 选脚心法（V2/V3 直接套用）

1. 模拟输入 → ADC1 组（32–39）；第二片 FSR 用 **D35**；
2. 数字输出/PWM → 干净普通脚（25/26/27/32/33 等）；
3. 避开 strapping 五脚与烧录占用的 1/3；
4. **21/22 留给 I2C**（将来 IMU 的位置）。
