# 板子解剖与三层刷机（第 1 层：程序住在哪里）

> 2026-11-03 开讲（L3 路线重排后第 1 层，决策三十三：未投课默认从零、不得依赖「在场经验」）。

## 概念定义

**【材料】**（ESPP32 通用事实 + 本课讲授；出处：ch01 旧笔记 notes/ch01_V1首读全链路原理.md 的 0.3 底稿 + 10-23 远距刷机实录）

**板子 = 没有屏幕/硬盘/键盘的极小计算机**：SoC（CPU+RAM）；Flash 存储芯片（「硬盘」，断电不丢，即串行通信课段①那颗 SPI flash）；GPIO 引脚（「键盘+显示器」）；UART/BLE（「网卡」）。外围：CH340（USB↔UART 翻译官）+ 稳压器（5V→3.3V）。

**程序住 three 层（按「谁来动它」分）**：

| 层 | 内容 | 类比 | 动它的频率 |
|---|---|---|---|
| 3 | main.py（应用） | 部署的应用脚本 | 日常只动这层 |
| 2 | MicroPython .bin（解释器+蓝牙协议栈，≈极简 OS） | OS+解释器合体 | 09-15 刷过一次，基本不再动 |
| 1 | bootloader（出厂固化） | BIOS/UEFI | 永远不动 |

**上电链条**：通电/复位 → bootloader 自检并看有无人刷机（有→刷机模式；无→加载第 2 层）→ MicroPython 初始化栈与文件系统 → 执行 flash 里的 main.py → 应用跑（读 D34/print/蓝牙）。

**排障第一问＝哪一层死的**：

| 症状 | 死在哪层 | 能救否 |
|---|---|---|
| 刷机工具认不到板 | 1（多见线/驱动） | 难 |
| 认得到、但完全不跑 Python | 2 | 能（重刷 .bin） |
| Python 能跑、无输出/无广播且每次复位一致 | 3（main.py） | 能（换好文件） |

## 学习过程

@2026-11-03
- **起点**：ch03 双坑课直接开讲撞墙——用户不认识「固件/双模/广播/bleak」等名词。退一层，重建「板子是什么、程序住哪里」。
- **理解确认（检验题）**：设 main.py 某行变量名错→NameError，上电后三层各如何？用户答：**「板子在第三层报错；蓝牙广播属于第三层所以不生效；蓝牙协议栈在第二层所以蓝牙本身 work，只是不会广播」**——链条完整、分层归因准确，无提示推出「外部看像全死、内部只死一层」。
- **补充锐化**：错行在 print 循环前则串口也 0 输出（表观全死）；复位重启无效（同一坏文件再死同一行）；「不能直接覆盖运行中的 main.py」的底层原因（拽自己头发）。

## 关键洞察

- 分层思维的实用价值：现象「板子死了」必须拆成「哪一层死了」，第 3 层死是可自愈的（换文件），第 1/2 层才是真故障。
- 「刷固件」一词在此语境有歧义：日常多指把 main.py 拷进板子（第 3 层），而非刷 .bin（第 2 层）。
