# 烧录实操三招与双坑（第 4 层）

> 2026-11-03~11-11 讲（L3 重排路线第 4 层；前置五层概念全部就位后，双坑首次「可读」）。

## 概念定义

**【材料】**（出处：ch03 课 §1 + notes/ch03_BLE无线化双坑.md + 20261023_远程刷固件三坑.md）

**mpremote 三招**（经 CH340 UART 连进板上的 REPL=板上命令行）：
- `cp main.py :main.py` 拷文件进 flash（送新剧本）
- `reset` 硬复位（bootloader→MicroPython→跑新 main.py）
- `exec "…"` 临时在 REPL 执行一段（从后门试一句话）

**exec 暗坑（逐帧）**：REPL 唯一，被 main.py 死循环占着 → exec 先发 Ctrl+C 打断 main.py 抢 REPL → 执行你的话 → 退出后无人恢复 main.py → 第 2 层（栈）活着、第 3 层（循环）死在半路 → 串口 0 行。两层都错：①查错对象（验的是第 2 层模块，想验的是第 3 层循环）；②验证动作毁掉验证对象（按急停查流水线）。
**验证纪律=裸读串口**：pyserial 安静听 2 秒，`毫秒,读数` 行在滚=第 3 层活着干活，全程不扰被测对象（ch01「电压表思维：观察不扰回路」的串口版）。用户直觉「没法热重载」→ 纠正为「打断且不自愈」。
**RTS 脉冲复位**：EN 脚接 CH340 的 RTS → pyserial 拉 RTS 0.1s=软件按复位键（远端排障用，10-23 实证）。

**双坑全彩版**：
- 坑一：`ble.irq(_irq)` 忘写=值班员没排班 → 事件没人接 → conn[0] 恒 -1 → 扫描/连接/订阅全✅但数据 0 行、无报错。教训：**「定义了」≠「挂上了」**。
- 坑二：`ble.irq(_irq)` 插在 `def _irq` 之前 → 执行序上名字未出生 → NameError → 出生段崩 → 外观「整板死」（串口 0 输出+广播消失），实为第 3 层单层死，复位重刷即愈（修法=写新文件→改名）。元教训：**改一行要脑内跑一遍出生段完整执行序**。
