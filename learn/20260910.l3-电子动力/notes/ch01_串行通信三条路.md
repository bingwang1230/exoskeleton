# 串行通信三条路：UART 异步对表 / SPI 时钟线 / USB 自时钟

> 2026-10-24 会话开讲（起因：ch03 裸重演开场检索题用户完全无法解析——串口物理层是 ch01 的欠账，从零补课）。

## 概念定义

**【材料】**（本次会话讲授，出处：ch03 课 notes/ch03_BLE烧录与固件课.md 开场检索题引出的 20261002 预检实录 + AI 讲授）

接收方的核心难题：线上电压一位位摆，**「这一位」从哪个瞬间开始、我该何时去读？」** 工程上三条路：

1. **同步通信（SPI）**：牵一根时钟线，发送方每位喊一声「读！」（边沿触发）。SCLK+MOSI+MISO+CS 四线，板内厘米级，几十 MHz。代价：偏斜（时钟沿与数据须同时干净到达，线一长就错位）+ 时钟线自身跳变耗电/辐射 EMI。
2. **异步通信（UART）**：不牵时钟线，事先对表=波特率（每秒位数，名出电报工程师 Émile Baudot，AI 补充通信史）。每字节帧=起始位(拉低)+8 数据位+停止位——起始位是「每字节现场对一次表」，故两表只需在 ~10 位内漂移不错位（几个百分点容忍）。TX/RX 两线，115200 常用，几米级。死穴：拍子不合=乱码且链路不报错（异步串口坏不坏全看内容）。
3. **自时钟（USB/以太网/PCIe）**：时钟嵌进数据波形（0/1 跳变沿兼任数据+节拍，特殊编码保证不长时间不跳），差分两线 D+/D−，12/480 Mbps。代价：需芯片内置 USB 控制器+收发电路。

**方案选择判据（本课核心结论）**：第一判据=**这段链路需要多快**（需要快才值得付 SPI/USB 的成本）；距离是速度的上限约束（距离逼你降速，降速后异步死穴自愈、同步优势清零——远距选异步不是憋的，是白牵时钟线）；几米以上物理层换差分（RS-485 外挂驱动）。

**板上实例（用户自己的板）**：flash ──SPI── ESP32 ──UART── CH340 ──USB── Mac。CH340=把 UART 慢流翻译成 USB 自时钟流的桥；经典款 ESP32（WROOM）无原生 USB 外设（AI 判断，标志=板上挂 CH340；S3/C3 有原生 USB 不需要桥）。

**stty 坑的机理**：stty=set tty，配的是内核 termios 老接口；macOS CH340 驱动不理 termios，stty 返回成功只是内核记账，拍子没到芯片 → 芯片停在默认 9600 听 115200 流 = 全程乱码。pyserial 走 IOSSIOSPEED ioctl 才真设进去（出处：notes/20261002_预检踩坑记录.md）。

## 学习过程

@2026-10-24
- **起点**：ch03 开场检索题（预检乱码根因三选一）完全无法作答——用户自述「问题里不知道的东西太多，不知道从哪问起」。题作废，从「波特率/CH340/乱码」地基补起。
- **提问链（高质量）**：为什么叫波特率→异步与代码 await 异步是不是一回事→同步是不是=按顺序、为什么同步要对表→stty 是什么→SPI 是什么→时钟线是否让数据少一半→**时钟线自己不用对表吗？它也是模拟波形，代价是什么？**（此问直接命中同步通信软肋：偏斜与信号完整性）→三条路是不是二选一→远距离是不是憋选 UART→为什么不全用自时钟。
- **理解确认**：段①②③判断题（flash/ESP32/CH340/Mac 链路分段选方案）：段① SPI ✅；段② 误答 SPI（纠正：是 UART，判据是速度需求+bootloader 生态，非距离）——纠错后由用户自己复述收口：「判据不是距离是速度，SPI 快但成本高，段②不需要那么快」✅；段③ 的提问（为什么不用第三条路）被引导发现 USB 本身就是第三条路。
- **甲/乙波特率变式题（10-24 补答）**：首答全反（甲乱乙正）——典型直觉误「收得快总没问题」；纠正（快接收方把一个位数成 12 个位；判据只有「相等」）后用户自主复述归位：「CH340 9600 就是匹配的正常，115200 乱码」。附带锚点：10-02 若把固件也改成 9600 即恢复，乱码从来不是因为「9600 不好」而是「两边不一样」。

## 关键洞察

- 「同步=现场指挥（时钟线），异步=事先对表（波特率）」——与代码 await 异步是撞名，两个维度。
- 异步不是完全不对表：起始位=每字节开头现场对一次。
- 速度需求是选方案第一判据；距离只是速度的上限。近距离≠该用 SPI（段② UART 就是反例）。
