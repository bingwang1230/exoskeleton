# 第二章：执行器与静力学（motor 力矩控制）

> 2026-09-04 会话（MBP exo-sim，commit 6438258）

## 1. position vs motor：为什么力矩控制才是外骨骼的正确抽象

- `<position kp="..."/>` = MuJoCo 包好的 PD 位置伺服，内部即 τ = kp·(θ* − θ)。
- OpenExo 真实链路：上层控制器算目标力矩 τ* → 电机底层 PD 跟踪 τ* → 减速 → 钢缆 → 关节。
- 结论：仿真用 `<motor>`，ctrl 直接是力矩指令（×gear），PD 环节留给 Python 自己写（为复现 PJMC 铺路）。

## 2. 静力学平衡：平衡角 = 力矩打平的位置

- 平衡条件：|ctrl·gear| = m·g·x_com·cosθ → θ = arccos(ctrl / (m·g·x_com))。
- leg0 脚：m=1kg，x_com≈0.06m → 重力矩 ≈0.59 N·m。viewer 手感估平衡 ctrl≈0.63，仿真精确复现 0.59 处 θ≈0°（水平）。
- 记忆锚点：「要多大力矩扛住重力」就是外骨骼电机选型的第一道算术题（AK80-9 额定 ~9 N·m × 4.5:1 滑轮同源）。

## 3. 踩坑：MJCF 角度默认是「度」

- 症状：踝被限位焊死在 ±0.7°，任何 ctrl 都不动，qfrc_constraint 出现大的 type-3（joint limit）约束力。
- 原因：`range="-0.8 0.6"` 被 MuJoCo 按度解读（0.6° = 0.0105 rad）。
- 修复：`<compiler angle="radian"/>`。**以后所有模型统一 radian**。

## 4. 符号纪律：新模型先做静力学符号检查

- 本模型正 ctrl 与重力同向（脚尖下沉方向）；静力学对拍发现 ctrl 需取负才能对抗重力。
- 外骨骼上控制符号反了 = 反向助力 = 安全事故。习惯：每个新模型先跑 statics_test 确认符号与量级。

## 5. 调试工具箱（本课用到）

- `data.qfrc_actuator` / `qfrc_passive` / `qfrc_bias`（重力+科氏）/ `qfrc_constraint` 四路力矩分解——「为什么不动」先看这四个数。
- `data.efc_type/efc_force`：3 = joint limit，定位限位卡死。
- `mj_resetData`：扫参数循环里必须重置，否则上一组姿态污染下一组。
