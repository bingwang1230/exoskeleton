## 误解与纠正记录(全章合并,详见各概念笔记)

| 原表述 | 纠正 |
|---|---|
| App 决定下一步动作→Nano→Teensy→电机(把 App 塞进主环) | ✗✗ 全章最危险误解(安全攸关):控制决策在 Teensy 本地 1kHz 闭环;App 只看数据+改规则;断连必须安全退化 |
| 参数会被 1kHz 遥测流冲掉 | 全双工两条独立车道,反向永不相撞 |
| 改参数的信息流会引入噪声坏遥测 | 数字消息不携带噪声;真风险=串扰(物理)/缓冲区溢出(软件) |
| Nano 经 CAN 把参数告诉 Teensy | 三段链路三协议:BLE(无线)/UART(独木桥)/CAN(电机);参数的腿永远是 UART |
| SD 卡=boot 文件,理论上改 SD 上的源码 | 固件在芯片内部 Flash(USB 烧录),SD 只是启动后读的数据盘;树莓派/GRUB 是反例,Arduino 生态选择代码/数据物理分离=双速系统物理化 |
| 「不准生长」理解为不能改参数 | 生长=造对象(动堆),不是写数值;字段随便写,堆不能动 |
| 断电持久化:App 自管参数即可 | 漏裸奔窗口(开机→连接前)+无 App 场景(户外/借穿);惯例双保险:SD 存最后已知好配置+App 对账 |

## 概念金句银行

- 通信是不确定的,控制是死节的——隔离在另一颗芯片是最笨也最硬的实时保证
- 遥测是生鲜,参数是合同——生鲜丢旧保新,合同必须签收回执
- 组合长树,策略做插件
- 数据树是跨芯片契约,计算树是芯片私产;封装是捆售,需求不均时成障碍(Nano 只要账本不要会计)
- 开机建好一切,循环里只准调用不准生长;字段随便写,堆不能动
- App 是仪表盘和遥控器,方向盘和发动机都在 Teensy(同构:Pixhawk+地面站)
- 关键安全链路上不允许出现软件和无线;断连必须退化,不许失控
- 配置=预设词表内的自由度,词表外=慢车道+重付抽象税(新曲线形状题=10% 落网之鱼的具象)
- 分钟级的卡和天级的芯片——双速系统的物理化身
- 方向翻转:左右腿的差异被压缩成一个布尔(实例间差异的极致压缩比)
- 大模型分界线:判据不是频率是断连后果(T-016,迁移到创始人对话)
