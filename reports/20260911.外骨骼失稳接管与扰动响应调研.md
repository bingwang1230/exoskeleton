# 外骨骼失稳接管与扰动响应调研（「滑/绊了立刻接管稳住」可能吗？「NN 必须 20ms」是伪约束吗？）

> 调研日期：2026-09-11。触发：用户提问「如果人滑了一下、绊了一下、失重时，外骨骼立刻接管帮人稳住，有可能吗？要怎么做，端侧神经网络加陀螺仪？神经网络的延迟必须在 20ms 内了吧」。
> 服务对象：① 工程线扰动控制的长期能力地图（Phase 3「步态相位检测」的自然延伸）② content 科普弹药（T-029）。
> 来源纪律：标注「原文」的数字均为本次逐篇打开论文核对；标注「转引」的为二手来源（见 §7 说明），其中 Pijnappels 60–80 ms 与 hip'air 气囊数字未开一手原文；§5–§6 工程建议均标「AI 设定，待确认」。检索工具 SearXNG 多引擎 + 浏览器打开原文（ScienceDirect/IOP/HAL 原文被反爬墙挡住的以转引标注）。
> 与《20260910.外骨骼助力延时要求.md》的关系：昨日报告回答「稳态助力晚到多少会变阻力」（100–200ms 实用窗）；本报告回答「扰动场景检测+响应的时序约束」，两份互为补充。

## 1. 一句话结论

**「立刻接管、替人稳住」超出当前文献证据；「抢在人肌反应之前辅助你自己稳住」已被实验证明可行。** 而「神经网络必须 20ms 内」是把约束放错了地方——

- **有效性的时序硬约束不是 NN 推理，是力矩落点**：站姿扰动实验（Beck 2023，原文）中，踝外骨骼力矩在扰动后 **41–68 ms** 开始压上 → 平衡阈值 **+9%**；同样的力矩拖到 **141–171 ms**（与生理反应同步）→ **无改善**（p=0.128）。结论即标题：*必须快于生理反应*（生理反应踝力矩约 **130 ms** 才出现）。
- **端侧算力早已不是瓶颈**：Beck 2023 用**树莓派 4B @200 Hz** 做加速度阈值检测，扰动检测延迟仅 **14±6 ms**；ML 滑步检测 SOTA（Peterson 2025，原文）用的是 **100 Hz** 采样 + 滑动窗口——采样与信号发散才是节拍器，不是推理。
- **检测的真实瓶颈是「信号需要时间才与正常步态分得开」**：滑步 ML 检测最快 **155 ms@96%**（XGBoost，髋外骨骼自带 IMU，已与人肌反应同步）；绊倒则根本不需要 ML——**脚尖 FSR 碰撞接触毫秒级触发**（Eveld 2023）；小滑步（~4 cm）在现有传感器下**不可检**（Peterson 2025，原文）。

## 2. 人体时序锚点（各场景的「必须多快」）

| 场景 | 生理锚点 | 助力要赶上谁 | 出处 |
|---|---|---|---|
| 绊倒（trip，摆动相） | 支撑腿肌电反应 60–80 ms；elevating 策略全程 ~450 ms | EMG 60–80 ms；完整恢复窗 ~450 ms | Pijnappels 系列（转引）；King 2019（经 Eveld 2023 原文转述） |
| 滑步（slip，支撑相） | 受扰腿肌肉激活 146–199 ms，未受扰腿 140–246 ms | 检出 ≤150 ms 即与人同步 | Peterson 2025 原文（转引其文献 [13][26]） |
| 站姿扰动（推/滑平台） | 比目鱼肌反应激活 101±14 ms；反应踝力矩 ~130 ms | **力矩起点 <100–130 ms** | Beck 2023 原文 |
| 消费级对照：髋部气囊腰带 | 检测跌倒 ~200 ms + 充气 ~80 ms（Helite hip'air 厂商口径） | 纯检测+被动保护的商用化水平 | 两篇综述转引（§7-5） |

**解读（AI 综合）**：三个场景的难度排序是 绊倒（易：接触即知）< 站姿扰动（中：加速度阈值 14 ms 可检出）< 滑步（难：信号逐渐发散，155 ms 才可靠分出）。「失重/踩空」类扰动文献最少（AI 推断：信号形态接近站姿扰动的整体加速度突变，阈值法可覆盖，待确认）。

## 3. 核心证据（逐篇）

### 3.1 Beck, Shepherd, Rastogi, Martino, Ting & Sawicki 2023 —— 「快于生理」的直接因果实验

- Beck ON, et al. *Exoskeletons need to react faster than physiological responses to improve standing balance.* Sci Robot 2023;8(75):eadf1080（全文 PMC10169237）。
- 设计：10 人站姿，平台后移扰动，双踝 Dephy ExoBoot 三条件对照——基线 / 人工快速力矩 / 生理延迟力矩。**树莓派 4B 读传感器 @200 Hz**，加速度阈值触发（后向 >147 cm/s²）。
- 关键数字（原文）：检测延迟 **14±6 ms**；命令→实测电流差 **27±5 ms**；快速力矩条件扰动后 **41–68 ms** 起力矩、50 ms 内爬到 **30 Nm**；生理延迟条件 **141–171 ms** 同样力矩曲线。
- 结果：快速 → 平衡阈值 **+9%**（p<0.001）；延迟 → **无差异**（p=0.128）。快速力矩削弱了踝局部本体感觉（比目鱼肌腱膜力 -73%），但全身性反馈仍驱动肌电（初始反应激活仅 -18%），人机未打架。
- 作者路线建议（原文）：触发信号应用**全局力学量（CoM 速度等）**而非局部关节/肌电——「预测并先于生理反应」。

### 3.2 Peterson, Leestema, Kang & Young 2025 —— 髋外骨骼自带传感器的 ML 滑步检测 SOTA

- Peterson RR, et al. *Machine Learning Enables Rapid Detection of Slips Using a Robotic Hip Exoskeleton.* IEEE Trans Med Robot Bionics 2025;7(2):666–677（PMC12363657）。
- 装置：1-DOF 髋外骨骼（4.78 kg），**3× MPU-9250 IMU**（双侧大腿+下背）+ 2 髋编码器，**100 Hz**，透明零阻抗模式。CAREN 分带跑台诱导早/晚支撑相滑步（midi~maxi 档），10 人 600 次扰动。
- 方法：20 ms 步进滑窗提特征（均值/方差/极值/末值），比 LDA / XGBoost / CNN。**小滑步（3.85±0.36 cm）检不出，直接剔除训练**。
- 结果（原文）：**XGBoost 最优——ES 滑步 155.06 ms 检出@96.25%，LS 228.88 ms@93.75%**；100% 灵敏度时 195.64/266.24 ms；ES 可换 +40.58 ms 得 100% 中位准确率。CNN 不如 XGBoost（小数据集喂不饱深度模型，作者原文明说）。
- 文献坐标（原文转述）：滑步检测此前最快 150–250 ms（Tropea，动捕）；外骨骼自带传感器实现 350 ms（Monaco 2017）；唯一报时间的 ML 法 351 ms。**本文首次把外骨骼自带 IMU 的 ML 检测推到与人肌反应（146–199 ms）同步**。

### 3.3 Eveld, King, Zelik & Goldfarb 2023 —— 膝外骨骼绊倒恢复助力（首个 dedicated 助力实证）

- Eveld ME, et al. *Efficacy of stumble recovery assistance in a knee exoskeleton for individuals with simulated mobility impairment: A pilot study.* Wearable Technol 2023;4:e22（PMC10952054）。
- 检测：**脚尖 FSR 直接测障碍物接触**（毫秒级，无需 ML）；嵌入式 1 kHz 控制。
- 助力：检出即触发 **450 ms 前馈力矩脉冲**（14.5 Nm 峰值，屈 225 ms + 伸 225 ms），匹配 elevating 策略时长。
- 结果：模拟负重受损的受试者，膝助力改善迈步腿运动学（大腿/膝活动度↑）、降低整体摔倒风险指标（躯干运动↓、落点更前置）。
- 两个对叙事重要的定位（原文）：①此前无人做过 dedicated 绊倒助力（Akiyama 2020 只试过「继续/停止行走助力」）；②作者把用途列为「给已有外骨骼穿戴者的安全机制」——**承认外骨骼本身增重/增阻尼会恶化绊倒恢复**。

### 3.4 Tagliaferri, Campeggi, Beck & Kang 2024/2025 —— 连续状态检测路线

- arXiv:2412.06985（ICORR 2025）。跟踪下肢运动学状态相对稳态轨迹的偏离，5 人先导：**98.8% 准确率，步态周期 23.1% 内检出**（按 1.2 s 周期换算 ≈280 ms，AI 换算），比全身角动量基准准确率高 47.7%。观点：全身角动量做外骨骼检测指标「计算延迟大、调参多，不适合」。

### 3.5 消费级对照：髋部气囊（纯检测+被动保护的商用化水位）

- Helite hip'air：跌倒检测 ~200 ms、气囊展开 ~80 ms。**厂商口径，经两篇学术综述一致转引**（J Phys Conf Ser 1790:012024；Eng/S2666188825010226），未开一手原文。意义：纯「检测+爆」的单次动作，商用系统也就做到 0.2 s 量级——「外骨骼连续力矩快于生理反应」是明显更高的门槛。

## 4. 「20ms」正面拆解（回答提问）

端到端链条逐环（数字出处见 §3）：

| 环节 | 量级 | 是否瓶颈 |
|---|---|---|
| 扰动物理发生→信号可分辨 | 滑步 ~150 ms（信息瓶颈）；绊倒 ~ms（接触）；站姿 ~14 ms（加速度阈值） | **滑步的真瓶颈** |
| NN/算法推理（端侧） | 树莓派阈值 14 ms 实证；LDA/XGBoost 在 MCU 为 ms 级（AI 常识推断，未单独找 benchmark 原文） | 否 |
| 低层控制+电流环 | 命令→实测电流 27±5 ms | 小 |
| 力矩爬升 | 30 Nm / 50 ms（Dephy 实证） | **次瓶颈（执行器带宽）** |
| 人-机接口传力（绑带柔顺） | 文献未定量（AI 判断：不可忽略） | 未知 |

**结论**：①「NN 推理 <20 ms」既不必要（力矩有效窗口的竞争对象是 100–130 ms 的生理反应，不是 20 ms）也不充分（滑步信号 150 ms 才分得开，NN 再快也没用）；②该写进指标的是三个量：**检测时延（按场景 15–160 ms 分级）、力矩起点（扰动后 <100 ms）、力矩爬升率（~30 Nm/50 ms 量级）**；③稳态助力的相位错位窗口（昨日报告：5–10% 步态周期）在扰动场景被替换为「先于生理反应」的绝对时序要求——两份报告合起来才是完整的延时地图。

## 5. 技术路线（怎么做——文献拼装 + AI 设定，待确认）

1. **传感**：外骨骼自带位 IMU（双侧大腿+躯干）+ 关节编码器 + 脚底 FSR（步态相位）+ 脚尖 FSR（绊倒接触）。Beck 建议传感器靠近 CoM（躯干 IMU 权重最高）。sEMG 最早（肌电先于力矩 30–50 ms）但穿戴成本高，暂不选（AI 设定）。
2. **检测三层架构**（避免单一 ML 包打天下）：
   - 事件层：FSR 接触/加速度阈值，ms 级，管绊倒与站姿突变；
   - 学习层：XGBoost/LDA 级小模型，100 Hz、20 ms 滑窗，管滑步（Peterson 已验证配方；CNN 在小数据下不划算）；
   - 状态层：CoM 速度连续估计 + 稳态轨迹偏离（Tagliaferri 路线），不做离散「检测」——Beck 的结论性建议。
3. **执行策略**：滑步→双侧髋伸展力矩；绊倒→膝屈伸 450 ms 脉冲（elevating 窗口）；站姿→踝跖屈。前提是执行器有 ~30 Nm/50 ms 的带宽（本项目踝构型选型时可把「力矩带宽」列为与峰值力矩同级的指标，AI 设定）。
4. **训练数据**：文献全靠 CAREN 类扰动平台（百万级设备，单人项目不可得）。替代：①安全吊带+跑台/绊索/低摩擦板自采（人体实验需过安全红线流程）；②仿真扰动注入批量造数据（exo-sim/MJX 强项），sim2real 损失未知，需真机小样本校验（AI 设定，待确认）。
5. **安全哲学**：扰动场景下**误触发比漏触发危险**（错拍大力矩=把人推倒）；fail-safe 动作应为「撤销助力+声光提示」而非「补大力矩」；任何对人出力矩的扰动响应，都排在假人盲测之后（三线计划 §7 红线，无需新决策）。

## 6. 对本项目的落点（AI 设定，待确认，不自动上板）

- **定位**：此能力是 Phase 3「L4 步态相位检测（IMU 阈值法→学习法）」的自然延伸，当前 Phase 1 无需投入；本报告只入弹药库与知识储备。
- **零成本可先做**（若用户想动）：exo-sim 注入滑/绊扰动数据集 + 离线训练检测器 + 评指标（不出力矩、纯软件，不碰安全线）——正好复用 MBP 的 MJX 批量能力。
- **选型留痕**：踝执行器选型时补「力矩带宽」指标（§5-3）；IMU 采样 ≥100 Hz 即可对齐文献配置。
- **内容线**：T-029 已登记（§7 素材伴随），核心叙事「外骨骼要抢在你肌肉前面出手，晚 100ms 就白干」。
